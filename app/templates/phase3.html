Phase 3

Model Engineering

Several suitable algorithms per task, the same protocol for all of them, a hyper-parameter search with cross-validation grouped by player, and every run written to the experiment log. Code: src/umbral_ml/train.py.

3.1 Candidates and why each one

Task 1 · next action (multiclass)

CandidateWhy it is a sensible choice here
Majority classLower bound: any useful model must beat it.
Global Markov-1 tableThe simplest sequence model, the same for everybody.
In-game Markov-2 with decay 0.97The deployed model: learns each player online, forgets slowly. Exact replica in online.py.
Tuned online MarkovSame idea with order and decay chosen by data (domain-guided tuning of the existing model).
Multinomial logistic regressionLinear, calibrated probabilities, tiny, easy to port to GDScript.
Random forestNon-linear interactions (life × distance × last action), robust.
Gradient boosting (HistGB)Strong on tabular data, handles missing values, good probabilities.

Task 2 · will the attack hit (binary, probabilistic)

Constant rate · in-game bandit (per-attack logistic regression trained by SGD, lr 0.3) · tuned bandit (learning rate) · logistic regression on the situation · logistic regression with attack × situation interactions · decision tree · random forest · HistGB.

Task 3 · dodge (2D regression)

No movement · global mean · in-game running mean (weight 1/min(n,8)) · per-player mean shrunk towards the global mean (k tuned).

3.4 How domain knowledge guided the decisions

  • Split by player, because the model must serve someone it has never seen (a new player opening the game).
  • The 4-second phrase rule and the order-2 context come from how combat works in the game (actions come in bursts).
  • Personal history features (hist_*, mk_*), because each player has a style (archer, brawler, turtle) that the bosses must learn quickly.
  • One slope per attack for the hit task: a feint beats a shield, ground waves are jumped — the effect of a situation depends on the attack.
  • Brier score for the hit task, because the boss compares probabilities between attacks: a well-calibrated 30% matters more than ranking.
  • Prequential evaluation of the online models, because in the game they predict first and learn afterwards.
